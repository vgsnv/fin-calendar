# Спецификация мобильного приложения · MVP

*Рабочее приложение для жизни по методу. Источник истины — [канон](../canon.md) (П), [сущности](../entities-and-rules.md) (С), [календарь](../calendar/index.md) (К, СВ); при противоречии правы они: здесь — только то, что касается приложения. Унаследованные интерфейсные решения старой Секции Б переведены на новый канон; сама она остаётся в архиве. Проверяемые требования пронумерованы (МП1…). Суммы и имена в примерах экранных фраз («выдать 12 000», «приход „Зарплата“») — иллюстрация, как сквозной пример канона: на экране всегда цифры из конфигурации и плана.*

---

## 1. Рамка

**МП1. Продукт** — рабочее приложение, не демонстрация: реальные данные, сохранение, живой пересчёт (П11).

**МП2. Платформа** — iOS нативно (SwiftUI), iPhone. Язык — только русский.

**МП3. Данные** — локально на устройстве, без бэкенда, авторизации и сети. Приложение не знает о банках ничего (П3, П4); всё его знание о реальности — план. Единственное сетевое действие — обновление справочника производственного календаря по явной кнопке в настройках (МП35); само оно план не меняет.

**МП4. Календарь v1** — только свой (СВ1–СВ6). Общий календарь не реализуется до закрытия вопроса ОБ2/ОБ4 (см. [spec-notes](../spec-notes.md)); развилка С18 в интерфейсе v1 не показывается.

**МП5. Опорные даты v1** — одна или две в месяц (даты приходов). Попытка завести третью — честное объяснение по К5: сетка от трёх дат не строится, общий календарь — в следующей версии. Молчаливых ограничений нет.

## 2. Принципы интерфейса

Унаследовано из старой Секции Б, сверено с новым каноном.

**МП6. Центр интерфейса — лента; главное действие — раскладка.** Лента отвечает на «в каком я состоянии», раскладка — на «что мне сейчас сделать». Нижней панели навигации нет: лента и есть навигация, всё достижимо с неё и из карточки спринта. Большой одинокой цифры на главном экране нет.

**МП7. Никакого учёта трат.** Нет ввода трат, категорий, чеков, сверок, диаграмм «куда ушло» — нигде, ни в каком виде (П3). Если пользователю захотелось записать трату — интерфейс провалился.

**МП8. Тревожного цвета не существует.** Ни красного, ни предупреждающе-тёплого. Любое состояние — включая несходящийся план — показывается нейтрально, с точной цифрой (П9).

**МП9. Правится цифра, а не человек.** Все подсказки — настройка плана («порция тесна — поднять?»), никогда оценка поведения («вы перерасходовали»). Прожитое не судится и не раскрашивается (П5).

**МП10. Система считает, человек решает** (П2). Везде, где есть выбор, — варианты с последствиями; молча система делает только то, у чего нет альтернатив (автопересчёт по П11).

**МП11. Варианты с последствиями** — сквозной элемент. Анатомия: *что меняется → что получается → чего это стоит*. Правила:

- вариантов два-три, не больше; всегда есть явное «оставить как есть»;
- первый — по порядку уступчивости (П8); выделений «рекомендуем» нет — порядок и есть вся иерархия;
- цена формулируется в единицах плана: рубли недели, даты, сдвиги;
- если бесплатного решения нет, хотя бы один вариант честно показывает цену (П9);
- порядок уступчивости — П8 (фонды → замыслы → даты платежей); возврат согнутого — обратный порядок (П6а);
- варианты появляются в ответ на действие человека. Сами приходят только два повода: «пора раскладка» и подтверждение пропущенной раскладки (С15а) — без ответа человека план перестаёт быть зрячим.

**МП12. Тон** — короткие фразы, бытовые слова, без финансового жаргона и подбадривания. Всё, что уже показано дизайном, голосом не дублируется.

## 3. Словарь интерфейса

Термины канона — во внутренней логике; на экране — правая колонка.

| В каноне | На экране |
|---|---|
| Финнеделя | неделя |
| Еженедельные деньги (С9) | еженедельные деньги |
| Спринт | спринт |
| Платёж с датой | платёж |
| Замысел | замысел |
| Фонд | фонд |
| Взнос | взнос |
| Раскладка | раскладка |
| Свободные деньги (П6а) | свободные деньги |
| Лишняя финнеделя длинного спринта (С9, С14) | дополнительная неделя |
| Недостача (П9) | «не хватает … к …» |
| Шлюз | «деньги ждут раскладки» |

Слов «инвариант», «балансировка», «скорость» на экране нет; скорость всегда конкретна: «5 000 в месяц», «2 500 с прихода».

## 4. Модель данных

Строго по [parameters.md](../parameters.md): редактируемо только перечисленное там; всё производное вычисляется и полем ввода не является.

**МП13. Конфигурация:** граница финнедели (рекомендация — суббота, С13) · дата входа. Порция еженедельных денег конфигурацией не является — еженедельные живут статьями плана (С9, МП15). Календарь в v1 зафиксирован («свой») и в интерфейсе не выбирается (МП4).

**МП14. Свой календарь:** опорные даты (в v1 равны датам приходов) · правило переноса на каждую дату (по умолчанию «последний рабочий день до») · производственный календарь — встроенный редактируемый справочник (СВ5).

**МП15. План:** приходы (имя · число месяца · ожидаемая сумма) и статьи четырёх видов с полями по С1–С9. Форма статьи следует из заполненных полей, а не из меню: сумма+дата — платёж, сумма+скорость — замысел, только скорость в месяц — фонд, только порция в неделю — еженедельные деньги.

**МП16. Прошлое хранится как факт.** Подтверждённые раскладки и прожитая часть сетки — неизменяемые записи (П5, П12): они не выводятся заново из текущих настроек. Любая правка действует от сегодня вперёд; ни один экран не предлагает редактировать прошлое.

**МП17. Движок отделён от интерфейса.** Расчёт (сетка, балансировка, пересчёт) — чистый Swift-модуль без UI, детерминированный, покрытый тестами по эталонам из `tests/` (кейсы балансировки 1–6 — приёмочные). Эталон сетки своего календаря нужно восстановить (см. открытые вопросы).

## 5. Структура

```
Вход (3 шага) → Лента
                 ├─ Карточка спринта → Раскладка (черновик → подтверждение)
                 ├─ Выдача (старт финнедели, с ленты)
                 ├─ Карточка статьи (маркеры ленты, взносы в карточках спринтов; создание — из карточки спринта)
                 └─ Настройки (с верха ленты)
```

## 6. Вход

По [practice.md](../practice.md) §4, три шага, меньше пяти минут:

**МП18. Шаг 1 · Приходы.** «Когда приходят деньги?» Одна-две строки: имя · число месяца · ожидаемая сумма; правило переноса — за раскрывашкой, по умолчанию «последний рабочий день до». Подпись: «Суммы примерные. Вносить весь доход не нужно — только то, из чего живёте».

**МП19. Шаг 2 · Статьи.** «Что вы уже знаете о будущих тратах?» Пустой список с «+»; создание — одна форма, вид определяется заполненными полями (МП15). Оценка — тоже сумма (С2).

**МП20. Шаг 3 · Еженедельные деньги.** «Сколько стоит неделя вашей жизни?» Поле суммы с живой проверкой «помещается / не помещается» и ссылкой «посчитать за меня» (поле заполняется расчётным максимумом; введённая руками цифра всегда главнее; молчаливого `min(заявленное, максимум)` не существует — при «не помещается» только развилка с вариантами). Шаг создаёт первую еженедельную статью (С9); разделить неделю на несколько статей можно позже — обычным созданием статей (МП15). Ниже — граница финнедели с рекомендацией субботы в одну строку. Кнопка «Посчитать».

**МП21. Вход рядом с длинным спринтом** показывается честно: окно сбора начинается со входа (С10), взнос дополнительной недели размазывается по имеющимся приходам; если не успевает — варианты по П8–П9, решение за человеком.

## 7. Лента

**МП22. Устройство.** Вертикальная лента, строка — финнеделя, спринты очерчены как фигуры (не линией-разделителем); у границы — дата старта, имя прихода, сумма. Календарная разметка полная: все семь дат с днями недели, бледные имена месяцев, отметки прожитых дней. Референс сетки — [прототип линейного календаря](../prototypes/linear-calendar/index.html).

**МП23. Прошлое сворачивается** в компактные строки-заголовки, разворачивается касанием, только чтение (МП16). **Будущее достраивается** при скролле вниз; предел — настройка, по умолчанию +5 лет.

**МП24. Маркеры будущего:** даты платежей · финиши замыслов · дополнительная неделя · недостача (П9) — засечка с точной цифрой и датой, варианты по МП11.

**МП25. Состояния строк.** Прожитая — приглушена, без оценок. Текущая — «вы здесь», ближайшая дата платежа; без большой суммы. Будущая — даты и маркеры.

**МП26. Вход в раскладку.** Между раскладками лента самодостаточна и ничего не хочет. Когда пора (наступила плановая дата прихода), у границы спринта появляется главный призыв экрана: «Приход „Зарплата“ · разложить». Неразложенный стартовавший спринт лента показывает явно: «план слеп до раскладки» (С12) — спокойно, без тревоги.

*Проекция дуг (длящиеся статьи как вертикальные линии с толщиной-долей) — кандидат в v2; в v1 — только календарная проекция с суммарной полоской занятости спринта.*

## 8. Раскладка

**МП27. Доступность и черновик.** Открывается с границы спринта с момента плановой даты прихода; до подтверждения — черновик, рекомендацию можно править (С12). Первая строка — фактическая сумма прихода, предзаполненная плановой: здесь план сверяется с реальностью, отличие пересчитывает рекомендацию на месте (П11). Если факт разошёлся с планом, черновик тихо предлагает обновить плановую сумму будущих приходов этого имени — одно касание, отказ ничего не меняет. Отдельного правила канона здесь нет намеренно: правка прихода — обычная правка плана.

**МП28. Чек-лист переводов.** Раскладка — список переводов, которые человек делает руками в своём банке; каждая строка отмечается отдельно, экран можно покинуть и вернуться. Порядок строк — рекомендуемый порядок исполнения: платежи → взносы замыслов и фондов → дополнительная неделя («собрано ранее») → еженедельные деньги спринта. Кнопка «всё проделано» отмечает всё разом. Отметка — исполнение собственного плана, не учёт факта (С12, П3).

**МП28а. Ручное распределение.** Из черновика раскладки и карточки спринта открывается экран «Распределение»: карточки неразложенных приходов, перетаскивание взносов между ними с живым пересчётом свободных денег и недостач, разбиение взноса ползунком, кнопка «Выровнять» — возврат к рекомендации (П6). Жёсткость П7 уважается с объяснением причины; тронутые руками строки автопересчёт не двигает.

**МП29. Свободные деньги.** Если после всех взносов у прихода остаётся излишек, раскладка показывает кнопку с цифрой; тап открывает попап вариантов строго в порядке П6а: вернуть согнутое (обратно порядку уступчивости) → ускорить существующие статьи → новое (замысел, еженедельная статья или повышение порции) — и последним всегда «ничего не трогать». Невостребованное с подтверждением выходит из плана и в следующих раскладках не фигурирует (С12а).

**МП30. Подтверждение** — явное действие; подтверждённая раскладка становится границей пересчёта (П12) и застывает (МП16).

**МП31. Пропущенная раскладка** — процедура С15а: на ближайшей раскладке по каждой статье вопрос «взносы пропущенного прихода были отложены?»; отложенные засчитаны, недобор перераспределяется общей балансировкой. Без упрёков и истории ответов.

## 9. Выдача

**МП32.** В старт финнедели на ленте у текущей строки — тихое действие: «Новая неделя · выдать 12 000». Всегда полная порция, никакого «дополнить до» (С16); одно касание, отметка, без экрана-праздника. Судьба неистраченного остатка нигде не отображается и не спрашивается.

## 10. Голос системы

**МП33. Ровно два уведомления,** каждое отключается отдельно. Оба — локальные push-уведомления самого приложения: сервера нет (МП3), расписание строится заранее из данных плана и перестраивается при каждой его правке (П11).

1. **Пора раскладка** — плановая дата прихода: «По плану сегодня приход „Зарплата“ — когда деньги придут, разложите их». Один раз на приход.
2. **Выдача** — утро старта финнедели: «Новая неделя · выдать 12 000». Один раз, это не будильник; если порция к этому моменту уже отмечена выданной, запланированное уведомление отменяется.

**МП34. Чего голос не делает:** не напоминает о незаконченной раскладке (видна с ленты), не анонсирует недостачи (уже стоят засечкой), не хвалит, не подводит итогов, не зовёт вернуться. Каждое уведомление — действие, которое пора сделать; уведомлений-новостей не существует.

## 11. Настройки

**МП35.** Конфигурация (МП13), приходы и правила переноса (МП14), производственный календарь, переключатели уведомлений, предел глубины ленты, округление отображения (канон отдаёт точные цифры — П10; округление живёт только в показе).

**МП36. Смена границы финнедели** — перезапуск по К7: приложение объясняет цену (сетка завершается, собранное выдаётся, вход заново с переносом статей и процедурой С15а) и требует явного подтверждения. Правка еженедельной статьи — обычная правка плана, не перезапуск (П11, П12): действует со следующей раскладки, текущий спринт доживает на прежних порциях.

**МП37. Роли счетов** ([practice.md](../practice.md) §2) — практика вне приложения: приложение о счетах не говорит и их не изображает (П4).

## 12. Крайние случаи — обязаны работать

1. Один приход в месяц → спринты по 4 финнедели, длинные по 5; экраны не меняются (К5).
2. Два прихода → спринты по 2, длинные по 3.
3. Третья опорная дата — честный отказ по МП5.
4. Производственный календарь: сетка считается до и после его учёта, расхождения показываются (СВ5) — январский стык не выглядит ошибкой.
5. Заявленная неделя не помещается → точное место и недостающая сумма (П9), никаких отрицательных чисел.
6. Приход пришёл не в плановую сумму → правится первой строкой раскладки (МП27), пересчёт вперёд.
7. Скролл на годы вперёд и в самый верх — без пустоты и заглушек; прошлое только читается.

- Проекция дуг на ленте — v2; критерий включения: календарная проекция v1 не отвечает на «что длится и когда кончится» без захода в статьи.
