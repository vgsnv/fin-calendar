# Свой календарь

*Календарь по опорным датам собственных приходов: старты спринтов идут за деньгами. Основа — «[Календарь](index.md)» (К1–К9); используется по умолчанию (К6). Правила — СВ1…*

---

**СВ1.** Опорные даты — даты собственных приходов денег.

**СВ2. Алгоритм сетки:**

```
1. Расставить номинальные опорные даты на весь горизонт.
2. Каждую прогнать через правило плательщика этой даты — одно из:
   *последний рабочий день до* (по умолчанию) · *первый рабочий
   день после* · *не переносится*.
3. Каждую фактическую дату сдвинуть вперёд до ближайшей границы
   финнедели (включая сам день) — это старт спринта (К2). Даты
   с одинаковым стартом складываются в один.
4. Старты по возрастанию — границы спринтов. Длина спринта —
   число финнедель до следующей границы (К3).
```

**СВ3. Проверочный инвариант.** Сумма длин всех спринтов между любыми двумя границами равна числу финнедель между ними — ни одна не потеряна и не посчитана дважды. Реализация, у которой это не сходится, неверна.

**СВ4. Длинный спринт** — спринт длиннее обычной длины своей опорной даты.

**СВ5. Производственный календарь** учитывается отдельным проходом: сетка считается до его учёта и после, расхождения показываются (кейс 4 в тестах: новогодние каникулы переносят длинный спринт на другую опорную дату).

**СВ6. Свойства:** старты стоят вплотную к приходам — деньги ждут раскладки не дольше шести дней; лента личная и перестраивается при смене графика приходов.

## Приложение А. Выводы из эталонов (`../tests/own-calendar-2027.md`)

- **Одна опорная дата в месяц (25-е):** спринты по 4 финнедели, несколько раз в год — по 5.
- **Две (5-е и 20-е):** спринты по 2, длинные — по 3, примерно раз в квартал.
- **Три (1-е, 10-е, 20-е):** обычные длины у спринтов разные, отклонения случаются в обе стороны — длина спринта просто вычисляемая величина.
