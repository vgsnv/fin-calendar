# fin-calendar

Метод личного финансового планирования (рабочее название линии — «Известное будущее») и материалы вокруг него.

## Структура

- `canon.md` — ядро метода в формате свода правил (П1–П12): термины, главный инвариант, роль системы, балансировка, пересчёт; мотивация — в приложении. Главный файл: при противоречии права он.
- `entities-and-rules.md` — из чего состоит план, свод правил (С1–С19): статьи четырёх видов (платежи с датой, замыслы, фонды, еженедельные деньги), спринт, раскладка, финнеделя, выдача.
- `parameters.md` — полный перечень внешних параметров системы и явный список производного; правил не создаёт, при противоречии правы канон и сущности.
- `calendar/` — устройство времени, отдельный каталог:
  - `index.md` — вход, свод правил (К1–К7): финнедели, спринты, опорные даты, рекомендуемые длины и выбор календаря;
  - `own.md` — календарь по датам приходов (по умолчанию): алгоритм сетки, длинные спринты, производственный календарь;
  - `common.md` — фиксированная лента, одна на всех: узор 2–2–2–2–2–3, правило года, високосный спринт.
- `practice.md` — как жить по методу руками: шлюз, роли счетов, вход.
- `spec/mvp.md` — спецификация мобильного приложения (МП1…): рабочее iOS-приложение, свой календарь, локальные данные; лента, раскладка, выдача, голос системы.
- `spec/screens/` — детализация экранов: `entry.md` (вход), `tape.md` (лента), `layout.md` (раскладка и распределение), `articles.md` (статьи), `issue.md` (выдача), `settings.md` (настройки).
- `spec-notes.md` — решения, накопленные для будущей спецификации приложения.
- `app/` — код приложения: Swift-пакет `FinCalendarCore` (расчётный движок без UI, МП17); тесты — прогоны эталонов из `tests/`.
- `prototypes/` — сборки прототипов; `linear-calendar/` — интерактивный линейный календарь (HTML/CSS/JS) с переключателем свой/общий.
- `tests/own-calendar-2027.md` — эталон своего календаря; `tests/common-calendar-2026-2032.md` — эталон общего. Приёмочные тесты для дизайнера и разработчика.
- `archive/` — устаревшие материалы: линия «Гибкие финансы» и старый канон со спецификацией прототипа.

## Правила ведения

- Решения о методе меняют `canon.md`; сущностные — `entities-and-rules.md` и `calendar/`; практические — `practice.md`. При противоречии права канон.
- Каждое содержательное изменение — отдельный коммит с внятным сообщением.
- Прошлые версии не редактируются — история и есть хронология.
